# 5. Процеси та мережні сервіси

Заготовки (`<USER>`, `<PID>` тощо) і позначки 🟢🟡🔴 дивись у [README](README.md).

## Терміни

**nice-значення** пріоритет процесу, від -20, найвищий, до 19, найнижчий. Звичайний користувач може лише підвищувати це число, тобто знижувати свій власний пріоритет.

**renice** змінює nice-значення вже запущеного процесу.

**сигнал** повідомлення, яке можна надіслати процесу командою `kill`. Не обов'язково означає "вбити".

**SIGSTOP/SIGCONT** призупинити процес і відновити його виконання.

**SIGKILL, -9** примусово й негайно завершує процес, без шансу прибратись за собою.

**порт, що слухає (listening)** програма чекає на ньому вхідні з'єднання.

**LISTEN/ESTABLISHED** стан TCP-з'єднання. LISTEN означає, що програма слухає порт. ESTABLISHED означає, що з'єднання вже активне.

## 5.1 Пріоритет і керування процесами 🟡

```bash
dd if=/dev/zero of=/dev/null &
dd if=/dev/zero of=/dev/null &
# dd if=/dev/zero of=/dev/null нескінченно копіює нулі в нікуди, навантажує CPU
# символ & запускає процес у фоні, керування терміналом повертається одразу

ps -eo pid,ni,time,cmd | grep "dd if"
# pid це номер процесу
# ni це поточне nice-значення
# time це скільки часу процесора вже використано

renice +10 -p <PID>
# renice +10 знижує пріоритет вказаного процесу, більше число означає менше CPU-часу
```

```bash
kill -STOP <PID>
# -STOP призупиняє процес, стан стає "T", зупинено

kill -CONT <PID>
# -CONT відновлює виконання

kill -9 <PID>
# -9, тобто SIGKILL, примусово завершує процес
```

Прибрати, якщо лишились фонові процеси

```bash
kill %1 %2
```

або

```bash
pkill dd
```

## 5.2–5.3 Відкриті мережні порти 🟢

```bash
sudo ss -tulpn
# -t означає TCP
# -u означає UDP
# -l показує лише порти, що слухають
# -p показує, який процес, PID і назву, тримає порт
# -n показує числові адреси й порти, без резолву імен, швидше

sudo netstat -tulpn
# netstat це старіший аналог ss, та сама ідея, часто теж доступний
```

Якщо результат порожній, крім заголовка, це означає, що в системі зараз жодна програма не слухає жоден порт. Немає сервісів, доступних ззовні.

## 6.2 Висновки: типові ознаки вразливостей

Обліковий запис у групі sudo або adm. Компрометація такого акаунту означає повний доступ до системи.

SUID-програми понад стандартний мінімум. Кожна зайва програма з SUID є потенційним вектором підвищення прав.

Правило sudo на скрипт, що належить не-root користувачу. Цей користувач може підмінити скрипт і виконати довільний код від root.

М'який umask, наприклад 002. Нові файли стають доступними на запис усій групі власника.

Відкритих портів немає, файлів без власника немає. Це зменшує поверхню атаки.

SUID не діє на скриптах, лише на скомпільованих програмах. Підвищення прав через скрипт неможливе без sudo.
