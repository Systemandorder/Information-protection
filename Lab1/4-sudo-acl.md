# 4. sudo для окремої команди та списки доступу ACL

Заготовки (`<USER>`, `<FILE>` тощо) і позначки 🟢🟡🔴 дивись у [README](README.md).

## Терміни

**sudoers** файл, який редагується лише через `visudo`. У ньому визначено, кому дозволено виконувати які команди від імені кого.

**NOPASSWD** спецопція в sudoers, яка дозволяє виконати команду без запиту пароля.

**ACL (Access Control List)** розширення стандартних прав Лінукса. Дозволяє призначити права не одній, а кільком групам чи користувачам окремо для одного файлу чи каталогу.

**default ACL** права, які автоматично успадкують усі нові файли й підкаталоги, створені в каталозі пізніше. Задаються лише для каталогів.

**маска ACL (mask)** верхня межа ефективних прав для всіх записів ACL, крім власника і інших.

## 4.4 sudo тільки для однієї команди 🔴

```bash
sudo visudo
# visudo це єдиний правильний спосіб редагувати sudoers
# він перевіряє синтаксис перед збереженням, щоб не зламати sudo для всієї системи

# всередині додати рядок
# <USER> ALL=(root) NOPASSWD: <SCRIPT>
```

Як читати цей рядок. `<USER> ALL=(root)` означає, що цьому користувачу, з будь-якого хоста, дозволено виконувати команду від root. `NOPASSWD:` означає без запиту пароля. `<SCRIPT>` означає, що дозволено лише оцей конкретний файл, нічого іншого.

```bash
sudo -u <USER> sudo <SCRIPT>
# перевірка, має виконатись одразу, без пароля, з uid=0, тобто root
```

Обмеження лише конкретним викликом, без аргументів

```bash
sudo visudo
# <USER2> ALL=(root) NOPASSWD: <SCRIPT> ""
# порожні лапки в кінці означають, що дозволений лише виклик без жодного аргументу

sudo -u <USER2> sudo <SCRIPT>
# пройде без пароля

sudo -u <USER2> sudo <SCRIPT> hello
# під правило вже не підпадає, тому sudo питає звичайний пароль
```

Якщо скрипт лежить у домашньому каталозі звичайного користувача і належить йому, таке правило небезпечне. Користувач може відредагувати файл і виконати від root що завгодно. Скрипти для sudo мають належати root і бути без права запису для інших.

## 4.6–4.7 Дві групи, один каталог, редактори і читачі, ACL 🔴

Чому звичайні права тут не підходять. У файла чи каталогу лише одна група власник. Щоб дати доступ другій групі, довелось би відкривати права категорії інші, а тоді їх отримають геть усі користувачі системи. Рішення це ACL.

```bash
sudo groupadd editors
sudo groupadd readers
sudo useradd -m editor1; sudo usermod -aG editors editor1
sudo useradd -m reader1; sudo usermod -aG readers reader1

mkdir <DIR>
setfacl -m g:editors:rwx <DIR>
# setfacl -m g:editors:rwx модифікує ACL, групі editors дає rwx

setfacl -m g:readers:r-x <DIR>
# групі readers дає лише читання і прохід, без w

setfacl -d -m g:editors:rwx <DIR>
setfacl -d -m g:readers:r-x <DIR>
# -d означає default, ці самі права автоматично успадкують усі файли й підкаталоги,
# створені в <DIR> у майбутньому

chmod o-rwx <DIR>
# забирає доступ категорії інші, щоб права визначались виключно членством у групах editors і readers
```

Перевірка

```bash
sudo -u editor1 sh -c 'echo hello > <DIR>/doc1.txt'
# дозволено

sudo -u reader1 cat <DIR>/doc1.txt
# дозволено, читає

sudo -u reader1 touch <DIR>/doc2.txt
# Permission denied

getfacl <DIR>
# getfacl показує повну конфігурацію ACL, базові записи плюс секцію default
```

Прибрати

```bash
sudo userdel -r editor1 reader1
sudo groupdel editors readers
rm -r <DIR>
```
