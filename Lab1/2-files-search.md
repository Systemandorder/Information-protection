# 2. Файлова система: пошук, відкриті файли, посилання 

Заготовки (`<USER>`, `<FILE>` тощо) і позначки 🟢🟡🔴 — дивитися [README](README.md).

## Терміни 

- **inode** — особиста картка файлу на диску: власник, права, розмір, де фізично лежать дані. Ім'я файлу — це лише запис у каталозі, що вказує на inode. Один inode може мати КІЛЬКА імен (жорстких посилань).
- **жорстке посилання (hard link)** — ще одне ім'я для того самого inode. Це не копія файлу, а другий "ярлик" на ті самі дані.
- **символічне посилання (symlink, soft link)** — окремий маленький файл, що містить лише ТЕКСТ шляху до іншого файлу. Якщо ціль видалити — посилання «б'ється» (не працює).
- **world-writable** — файл чи каталог, у який можуть писати (змінювати) взагалі ВСІ користувачі системи, не лише власник чи група.
- **SUID/SGID/sticky bit** — спеціальні позначки прав, детально пояснені в [3-permissions.md](3-permissions.md). Тут вони лише шукаються командою `find`.
- **PID** (Process ID) — унікальний номер запущеного процесу (програми, що виконується).
- **файловий дескриптор (FD)** — номер, яким процес всередині себе позначає відкритий файл (аби не передавати щоразу повний шлях).
- **stdin/stdout/stderr** — три стандартні канали процесу: ввід, звичайний вивід, вивід помилок. У `lsof` їм відповідають FD 0, 1, 2.

## Про команду `find`

Схема: `find <ДЕ_ШУКАТИ> <УМОВИ> <ДІЯ>`.

| Умова | Означає |
|---|---|
| `-name '*.conf'` | ім'я за шаблоном (`-iname` без урахування регістру) |
| `-type f` / `d` / `l` | файл / каталог / символічне посилання |
| `-user <USER>` / `-group <GROUP>` | належить користувачу / групі |
| `-nouser` / `-nogroup` | власник/група **видалені** (UID/GID без запису в passwd/group) |
| `-perm 644` | права **точно** 644 |
| `-perm -4000` | **усі** перелічені біти встановлені |
| `-perm /4000` | **хоча б один** з бітів встановлений |
| `-newermt 'YYYY-MM-DD HH:MM'` | змінено **пізніше** вказаного часу |
| `-xdev` | не виходити за межі одного розділу (швидше, без /proc, /sys) |
| `-links +1` | більше однієї жорсткої лінки |
| `-xtype l` | **биті** символічні посилання |

Дія за замовчуванням `-print`. Зручні: `-ls` (докладний вивід) і `-exec <команда> {} +`.

> **Чому `find ... | xargs ls -ldb {} \;` дає дивні повідомлення?** `{}` і `\;` — це синтаксис саме `find -exec`. Якщо передати список через `xargs`, вони потрапляють у `ls` як імена файлів і виникають помилки `cannot access '{}'`. Правильно  або `find ... -ls`, або `find ... -exec ls -ldb {} +`.

## 3.1 Пошук за шаблоном

### 3.1.1 Файли без власника або без групи 🟢

```bash
sudo find / -xdev \( -nouser -o -nogroup \) -ls 2>/dev/null
# find /              — шукати від кореня файлової системи
# -xdev               — не заходити в інші розділи (напр. /proc, /sys — там це не має сенсу)
# \( -nouser -o -nogroup \) — умова "АБО": UID власника не існує, АБО GID групи не існує
# -ls                 — докладний вивід (як ls -l), одразу без хитрощів з xargs
# 2>/dev/null         — приховати повідомлення "Permission denied" там, куди немає доступу
```
Знайдені файли небезпечні тим, що новий користувач із таким самим UID автоматично «успадкує» їх.

### 3.1.2 Доступні на запис усім (world-writable) 🟢

```bash
sudo find / -xdev -perm -0002 ! -type l -ls 2>/dev/null
# -perm -0002   — встановлено біт запису для "інших" (world-writable)
# ! -type l     — ВИКЛЮЧИТИ символічні посилання (у них права завжди rwxrwxrwx,
#                 це не загроза, лише засмічує вивід)
```
Каталоги зі sticky bit (як `/tmp`) нормальні. Небезпечні файли й каталоги **без** sticky.

### 3.1.3 SUID, SGID, Sticky 🟢

```bash
sudo find / -xdev -perm -4000 -type f -ls 2>/dev/null
# -perm -4000   — встановлено SUID: програма виконується з правами ВЛАСНИКА файлу

sudo find / -xdev -perm -2000 -ls 2>/dev/null
# -perm -2000   — встановлено SGID: з правами ГРУПИ файлу

sudo find / -xdev -perm -1000 -type d -ls 2>/dev/null
# -perm -1000   — sticky bit (лише для каталогів): видаляти файл може лише його власник
```
Кожна SUID-програма власності root — це потенційна ціль для атак із підвищенням прав.

### 3.1.4 Файли з датою з майбутнього 🟡

```bash
touch -d '2035-01-01' <FILE>
# touch -d '2035-01-01'   — створити файл із датою модифікації в МАЙБУТНЬОМУ
#                           (навмисно, щоб було що знаходити далі)

sudo find / -xdev -newermt now -ls 2>/dev/null
# -newermt now   — знайти об'єкти, змінені ПІЗНІШЕ, ніж поточний момент
```
Нормально, якщо знайдеться лише твій тестовий файл. Прибрати: `rm <FILE>`.

### *3.1.5 Атрибути append / immutable 🟢

```bash
sudo lsattr -R / 2>/dev/null | awk '$1 ~ /^[-a-zA-Z]+$/ && $1 ~ /[ai]/'
# lsattr -R          — рекурсивно показати розширені атрибути (не ті, що в ls -l!)
# $1 ~ /^[-a-zA-Z]+$/ — перша колонка (рядок прапорців) складається лише з літер і "-"
#                       (відсіює рядки-заголовки "/шлях:")
# $1 ~ /[ai]/        — у цій колонці є літера 'a' (append) або 'i' (immutable)
```
Демонстрація дії — [3-permissions.md](3-permissions.md#атрибути-chattr).

## 3.2 Які файли відкриті і ким 🟢

```bash
sudo lsof | head -30
# lsof (list open files) — показує всі відкриті файли в системі
# head -30                — обмежити вивід 30 рядками (список дуже довгий)

sudo lsof -u <USER>
# -u <USER>   — лише файли, відкриті цим користувачем

sudo lsof <FILE>
# lsof <FILE> — хто саме тримає цей файл відкритим прямо зараз

sudo fuser -v <FILE>
# fuser -v   —  які процеси використовують файл
```
Колонки `lsof`: `COMMAND` — програма; `PID`; `USER`; `FD` — дескриптор (`cwd` робочий каталог, `txt` виконуваний файл, `mem` бібліотека в пам'яті); `NAME` — шлях.

## 3.3 Жорсткі посилання та inode 🟡

```bash
touch <FILE>
# touch   — створити порожній файл

ln <FILE> <LINK>
# ln (без -s!)   — створити ЖОРСТКЕ посилання: друге ім'я для того самого inode

ls -li <FILE> <LINK>
# -l   — докладний формат
# -i   — показати номер inode ПЕРШОЮ колонкою (у обох файлів він буде ОДНАКОВИЙ)

find / -xdev -samefile <FILE> 2>/dev/null
# -samefile <FILE>   — знайти ВСІ імена, що вказують на той самий inode, що й <FILE>
```
Прибрати: `rm <FILE> <LINK>`.

## 3.4 Чи однакові два  однакових файли 🟢

```bash
diff <FILE1> <FILE2>
# diff   — порівнює файли порядково і показує, ЧИМ саме вони відрізняються

sha256sum <FILE1> <FILE2>
# sha256sum   — порахувати контрольну суму кожного файлу:
#               однакові суми = файли ідентичні до останнього байта
```
Як читати `diff`: `1c1` означає, що рядок 1 ЗМІНЕНО (**c**hange); `<` — рядок із першого файлу, `>` — із другого.

## *3.5 Биті символічні посилання 🟢

```bash
sudo find / -xdev -xtype l 2>/dev/null
# -xtype l   — знайти символічні посилання, чия КІНЦЕВА ціль (після розкриття шляху)
#              не існує — тобто "бите" посилання
```
*Коли жорстке посилання може вказувати на неіснуючий об'єкт?* У нормальній файловій системі  ніколи.Поки лічильник імен на inode більший за нуль, дані фізично не видаляються.
