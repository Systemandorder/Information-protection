# 2. Файлова система: пошук, відкриті файли, посилання

Заготовки (`<USER>`, `<FILE>` тощо) і позначки 🟢🟡🔴 дивись у [README](README.md).

## Терміни

**inode** особиста картка файлу на диску. Там зберігається власник, права, розмір і місце, де фізично лежать дані. Ім'я файлу це лише запис у каталозі, що вказує на inode. Один inode може мати кілька імен, тобто кілька жорстких посилань.

**жорстке посилання (hard link)** ще одне ім'я для того самого inode. Це не копія файлу, а другий ярлик на ті самі дані.

**символічне посилання (symlink, soft link)** окремий маленький файл, що містить лише текст шляху до іншого файлу. Якщо ціль видалити, посилання стає битим і не працює.

**world-writable** файл чи каталог, у який можуть писати взагалі всі користувачі системи, не лише власник чи група.

**SUID/SGID/sticky bit** спеціальні позначки прав, детально пояснені в [3-permissions.md](3-permissions.md). Тут вони лише шукаються командою `find`.

**PID (Process ID)** унікальний номер запущеного процесу.

**файловий дескриптор (FD)** номер, яким процес всередині себе позначає відкритий файл, щоб не передавати щоразу повний шлях.

**stdin/stdout/stderr** три стандартні канали процесу: ввід, звичайний вивід і вивід помилок. У `lsof` їм відповідають FD 0, 1 і 2.

## Про команду find

Загальна схема `find <де шукати> <умови> <дія>`.

| Умова | Означає |
|---|---|
| `-name '*.conf'` | ім'я за шаблоном, `-iname` без урахування регістру |
| `-type f` / `d` / `l` | файл, каталог або символічне посилання |
| `-user <USER>` / `-group <GROUP>` | належить користувачу або групі |
| `-nouser` / `-nogroup` | власник або група видалені, UID чи GID без запису в passwd/group |
| `-perm 644` | права точно 644 |
| `-perm -4000` | усі перелічені біти встановлені |
| `-perm /4000` | хоча б один з бітів встановлений |
| `-newermt 'YYYY-MM-DD HH:MM'` | змінено пізніше вказаного часу |
| `-xdev` | не виходити за межі одного розділу, швидше і без /proc, /sys |
| `-links +1` | більше однієї жорсткої лінки |
| `-xtype l` | биті символічні посилання |

Дія за замовчуванням `-print`. Зручні також `-ls` для докладного виводу і `-exec <команда> {} +`.

Команда `find ... | xargs ls -ldb {} \;` дає дивні повідомлення, бо `{}` і `\;` це синтаксис саме `find -exec`. Якщо передати список через `xargs`, вони потрапляють у `ls` як імена файлів і виникають помилки `cannot access '{}'`. Правильніше використовувати `find ... -ls` або `find ... -exec ls -ldb {} +`.

## 3.1 Пошук за шаблоном

### 3.1.1 Файли без власника або без групи 🟢

```bash
sudo find / -xdev \( -nouser -o -nogroup \) -ls 2>/dev/null
# find / шукає від кореня файлової системи
# -xdev не дозволяє заходити в інші розділи, там, наприклад у /proc чи /sys, це не має сенсу
# \( -nouser -o -nogroup \) це умова АБО: UID власника не існує, або GID групи не існує
# -ls дає докладний вивід, як ls -l, одразу без хитрощів з xargs
# 2>/dev/null приховує повідомлення Permission denied там, куди немає доступу
```

Знайдені файли небезпечні тим, що новий користувач із таким самим UID автоматично успадкує їх.

### 3.1.2 Доступні на запис усім, world-writable 🟢

```bash
sudo find / -xdev -perm -0002 ! -type l -ls 2>/dev/null
# -perm -0002 означає, що встановлено біт запису для "інших"
# ! -type l виключає символічні посилання, у них права завжди rwxrwxrwx,
# це не загроза, а лише засмічує вивід
```

Каталоги зі sticky bit, як `/tmp`, нормальні. Небезпечні ті, що без sticky.

### 3.1.3 SUID, SGID, sticky 🟢

```bash
sudo find / -xdev -perm -4000 -type f -ls 2>/dev/null
# -perm -4000 означає, що встановлено SUID, програма виконується з правами власника файлу

sudo find / -xdev -perm -2000 -ls 2>/dev/null
# -perm -2000 означає, що встановлено SGID, з правами групи файлу

sudo find / -xdev -perm -1000 -type d -ls 2>/dev/null
# -perm -1000 це sticky bit, лише для каталогів, видаляти файл може лише його власник
```

Кожна SUID-програма власності root є потенційною ціллю для атак із підвищенням прав.

### 3.1.4 Файли з датою з майбутнього 🟡

```bash
touch -d '2035-01-01' <FILE>
# touch -d '2035-01-01' створює файл із датою модифікації в майбутньому,
# навмисно, щоб було що знаходити далі

sudo find / -xdev -newermt now -ls 2>/dev/null
# -newermt now шукає об'єкти, змінені пізніше, ніж поточний момент
```

Нормально, якщо знайдеться лише твій тестовий файл. Прибрати: `rm <FILE>`.

### *3.1.5 Атрибути append / immutable 🟢

```bash
sudo lsattr -R / 2>/dev/null | awk '$1 ~ /^[-a-zA-Z]+$/ && $1 ~ /[ai]/'
# lsattr -R рекурсивно показує розширені атрибути, не ті, що видно в ls -l
# $1 ~ /^[-a-zA-Z]+$/ перевіряє, що перша колонка складається лише з літер і дефіса,
# це відсіює рядки заголовків виду "/шлях:"
# $1 ~ /[ai]/ перевіряє, що в цій колонці є літера a (append) або i (immutable)
```

Демонстрація дії атрибутів є в [3-permissions.md](3-permissions.md#атрибути-chattr).

## 3.2 Які файли відкриті і ким 🟢

```bash
sudo lsof | head -30
# lsof, list open files, показує всі відкриті файли в системі
# head -30 обмежує вивід 30 рядками, бо список дуже довгий

sudo lsof -u <USER>
# -u <USER> показує лише файли, відкриті цим користувачем

sudo lsof <FILE>
# lsof <FILE> показує, хто саме тримає цей файл відкритим прямо зараз

sudo fuser -v <FILE>
# fuser -v показує, які процеси використовують файл
```

Колонки `lsof`. `COMMAND` це програма, `PID` номер процесу, `USER` користувач, `FD` дескриптор (`cwd` робочий каталог, `txt` виконуваний файл, `mem` бібліотека в пам'яті), `NAME` шлях до файлу.

## 3.3 Жорсткі посилання та inode 🟡

```bash
touch <FILE>
# touch створює порожній файл

ln <FILE> <LINK>
# ln без -s створює жорстке посилання, друге ім'я для того самого inode

ls -li <FILE> <LINK>
# -l докладний формат
# -i показує номер inode першою колонкою, у обох файлів він буде однаковий

find / -xdev -samefile <FILE> 2>/dev/null
# -samefile <FILE> знаходить усі імена, що вказують на той самий inode, що й <FILE>
```

Прибрати: `rm <FILE> <LINK>`.

## 3.4 Чи однакові два схожих файли 🟢

```bash
diff <FILE1> <FILE2>
# diff порівнює файли порядково і показує, чим саме вони відрізняються

sha256sum <FILE1> <FILE2>
# sha256sum рахує контрольну суму кожного файлу,
# однакові суми означають, що файли ідентичні до останнього байта
```

Як читати `diff`. Запис `1c1` означає, що рядок 1 змінено, літера c означає change. Символ `<` показує рядок із першого файлу, `>` із другого.

## *3.5 Биті символічні посилання 🟢

```bash
sudo find / -xdev -xtype l 2>/dev/null
# -xtype l знаходить символічні посилання, чия кінцева ціль після розкриття шляху
# не існує, тобто це биті посилання
```

Коли жорстке посилання може вказувати на неіснуючий об'єкт? У нормальній файловій системі ніколи. Поки лічильник імен на inode більший за нуль, дані фізично не видаляються.
