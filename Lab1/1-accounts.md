# 1. Облікові записи, групи, паролі (розділ 2 методички)

Про заготовки (`<USER>` тощо) і позначки 🟢🟡🔴 дивись у [README](README.md).

## Терміни

**UID (User ID)** унікальний номер користувача в системі. Для ядра Лінукса кожне ім'я, наприклад "anna", насправді лише номер. UID 0 завжди належить root, суперкористувачу. Системні службові акаунти мають UID до 999, звичайні людські від 1000.

**GID (Group ID)** те саме, але номер групи, а не користувача.

**основна група (primary group)** одна єдина група, яка автоматично присвоюється кожному новому файлу, що створює користувач. У Kali та Debian типово для кожного користувача одразу створюється особиста група з таким самим іменем.

**додаткові групи (supplementary groups)** усі інші групи, до яких входить користувач, наприклад sudo, щоб мати право на sudo.

**shell, оболонка входу** програма, яка запускається, коли користувач входить у систему, наприклад `/bin/bash`. Якщо замість неї стоїть `/usr/sbin/nologin`, вхід у систему неможливий узагалі.

**хеш (hash)** незворотний відбиток пароля. Система зберігає не сам пароль, а його хеш. При вході вона хешує введене і порівнює з тим, що збережено.

**root** суперкористувач, UID 0, для якого майже всі перевірки прав доступу не діють.

**сесія входу** період від моменту, коли користувач увійшов у систему, до виходу.

## Три файли, в яких усе зберігається

| Файл | Що там | Хто читає |
|---|---|---|
| `/etc/passwd` | список користувачів | усі |
| `/etc/shadow` | хеші паролів і терміни їх дії | лише root |
| `/etc/group` | список груп і їхніх учасників | усі |

### Поля /etc/passwd, розділювач двокрапка

```
anna:x:1001:1001:Anna K.:/home/anna:/bin/bash
 1   2  3    4      5        6          7
```

Поле 1 це ім'я користувача. Поле 2, літера x, означає, що хеш пароля треба дивитись у `/etc/shadow`. Раніше хеш лежав прямо тут, зараз уже ні, з міркувань безпеки. Поле 3 це UID. Поле 4 це GID основної групи. Поле 5 це коментар, повне ім'я, необов'язково. Поле 6 це домашній каталог, де лежать особисті файли користувача. Поле 7 це shell, оболонка входу.

### Поля /etc/shadow

```
anna:$y$j9T$...хеш...:20734:0:99999:7:::
 1         2             3   4   5   6 7 8 9
```

Поле 1 ім'я. Поле 2 хеш. Якщо на початку стоїть `*` або `!`, вхід по паролю заблоковано. Якщо поле порожнє, пароля немає зовсім, вхід без пароля. Поле 3 дата останньої зміни пароля, число днів, що минули від 1 січня 1970 року, це стандартна точка відліку в Unix, звана epoch. Поле 4 мінімальна кількість днів між змінами пароля. Поле 5 максимальний термін дії пароля в днях, 99999 це приблизно 273 роки, тобто практично ніколи не застаріває. Поле 6 за скільки днів до завершення терміну попереджати користувача. Поле 7 скільки днів акаунт може бути неактивним після закінчення пароля, перш ніж заблокується. Поле 8 конкретна дата, у тих самих днях від 1970, коли акаунт вимкнеться повністю. Поле 9 зарезервоване, зараз не використовується.

### Поля /etc/group

```
team:x:1002:anna,bob
  1  2   3      4
```

Поле 1 назва групи. Поле 2, літера x, це пароль групи, застаріла можливість, майже ніде не використовується. Поле 3 GID. Поле 4 список учасників через кому. Важливо, що тут перелічені лише ті, для кого ця група додаткова. Якщо група основна для користувача, вказана в 4 полі `/etc/passwd`, у цьому списку його імені може не бути.

## 2.1 Аналіз підсистеми автентифікації

### 2.1.1 Які є облікові записи 🟢

```bash
cut -d: -f1 /etc/passwd
# cut вирізає колонку з тексту
# -d: означає, що розділювач полів це двокрапка, бо саме так розділений /etc/passwd
# -f1 бере лише перше поле, тобто ім'я користувача
```

### 2.1.2 Хто зараз увійшов 🟢

```bash
who
# who показує коротко, хто увійшов, термінал і час входу

w
# w показує те саме, що who, плюс що кожен користувач зараз робить

last -n 10
# last показує історію входів з журналу /var/log/wtmp
# -n 10 обмежує вивід останніми 10 записами
```

### 2.1.3 Локально чи віддалено 🟢

```bash
who -a
# who -a показує повну інформацію про сесії, включно з джерелом входу в дужках у кінці рядка
```

Як читати дужки в кінці рядка. Якщо там `(:0)` або порожньо, а термінал tty1 чи seat0, це означає локальний вхід, з фізичної чи віртуальної консолі цього ж комп'ютера. Якщо там IP адреса або ім'я хоста, а термінал має вигляд pts/N, це значить віддалений вхід, наприклад через SSH.

### 2.1.4 Акаунти, створені після встановлення 🟢

```bash
grep -E '^UID_MIN|^UID_MAX' /etc/login.defs
# grep -E шукає за розширеним регулярним виразом
# шаблон означає рядки, що починаються з UID_MIN або UID_MAX
# /etc/login.defs це конфігураційний файл, де задані межі UID для нових користувачів

awk -F: '$3 >= 1000 && $3 != 65534 {print $1, $3}' /etc/passwd
# awk -F: встановлює розділювач полів двокрапку
# $3 це третє поле рядка, тобто UID
# умова >= 1000 вибирає звичайні, не системні акаунти, що створюються вручну
# && $3 != 65534 виключає службовий акаунт nobody, його UID саме 65534
# {print $1, $3} виводить ім'я та UID
```

### 2.1.5 Групи 🟢

```bash
cut -d: -f1 /etc/group
# cut -d: -f1 бере перше поле, тобто назву групи, той самий принцип, що й для passwd
```

### 2.1.6 Хто в якій групі 🟢

```bash
getent group | awk -F: '$4 != "" {print $1": "$4}'
# getent group читає базу груп системи, надійніше за прямий cat /etc/group,
# бо бачить і зовнішні джерела, наприклад мережні каталоги
# $4 != "" лишає тільки групи, у яких список учасників, четверте поле, не порожній
# {print $1": "$4} виводить назву групи і учасників

for u in $(cut -d: -f1 /etc/passwd); do echo "$u: $(id -Gn "$u")"; done
# for u in $(...) перебирає по черзі всіх користувачів із /etc/passwd
# id -Gn "$u" виводить назви всіх груп користувача, включно з основною,
# яку попередня команда не показує
```

### 2.1.7 Хто лише в одній групі 🟢

```bash
for u in $(cut -d: -f1 /etc/passwd); do
  [ "$(id -G "$u" | wc -w)" -eq 1 ] && echo "$u"
done
# for u in $(...) перебирає всіх користувачів
# id -G "$u" дає номери, GID, усіх груп користувача, через пробіл
# wc -w рахує кількість слів, тобто кількість груп
# умова -eq 1 означає рівно одну групу
# && echo "$u" виводить ім'я, якщо умова істинна
```

### 2.1.8 Хто не може увійти 🟢

```bash
grep -E '(/nologin|/false)$' /etc/passwd | cut -d: -f1
# grep -E шукає за розширеним регулярним виразом
# шаблон означає, що рядок закінчується на /nologin або /false, це сьоме поле, shell
# cut -d: -f1 бере з відібраних рядків лише ім'я користувача
```

### 2.1.9 Без пароля 🟢

```bash
sudo awk -F: '$2 == "" {print $1}' /etc/shadow
# sudo потрібен, бо /etc/shadow читає лише root
# $2 == "" означає, що друге поле, хеш пароля, порожнє, тобто пароля немає зовсім
# {print $1} виводить ім'я такого користувача

sudo awk -F: '$2 == "*" || $2 ~ /^!/ {print $1}' /etc/shadow
# $2 == "*" означає, що хеш дорівнює зірочці, вхід по паролю неможливий, службовий акаунт
# $2 ~ /^!/ означає, що хеш починається зі знаку оклику, акаунт заблоковано
```

### 2.1.10 Хеші, замасковано 🟢

```bash
sudo awk -F: 'BEGIN{OFS=":"} { if ($2 ~ /^\$/) $2="***MASKED***"; print }' /etc/shadow
# BEGIN{OFS=":"} задає вихідний розділювач теж двокрапку, щоб формат рядка не зламався
# умова if ($2 ~ /^\$/) перевіряє, чи хеш починається зі знаку долара, тобто реальний хеш
# $2="***MASKED***" замінює його на маску
# print виводить увесь змінений рядок
```

### 2.1.11 Яка геш-функція 🟢

```bash
sudo cut -d: -f2 /etc/shadow | grep '^\$' | cut -d'$' -f2 | sort | uniq -c
# cut -d: -f2 бере лише друге поле, хеш, з кожного рядка shadow
# grep '^\$' лишає тільки рядки, що починаються зі знаку долара, реальні хеші
# cut -d'$' -f2 розбиває тепер за знаком долара і бере другу частину, код алгоритму
# sort | uniq -c рахує, скільки разів зустрічається кожен алгоритм

grep ENCRYPT_METHOD /etc/login.defs
# grep ENCRYPT_METHOD шукає рядок конфігурації, який алгоритм система використовує
# за замовчуванням для нових паролів
```

Коди алгоритмів такі. `$1$` MD5, застарілий. `$5$` SHA-256. `$6$` SHA-512. `$y$` yescrypt, сучасний, за замовчуванням у Kali. `$2b$` bcrypt.

### 2.1.12 John the Ripper 🟡

```bash
sudo apt install john
# apt install john встановлює програму для перебору й перевірки стійкості паролів

sudo unshadow /etc/passwd /etc/shadow > ~/hashes.txt
# unshadow об'єднує passwd і shadow в один файл формату, зрозумілого John
# > ~/hashes.txt зберігає результат у файл у домашньому каталозі

chmod 600 ~/hashes.txt
# chmod 600 закриває читання файлу для інших користувачів, бо там хеші паролів,
# сам власник читає і пише, усі інші нічого

john --format=crypt --wordlist=/usr/share/john/password.lst --rules ~/hashes.txt
# --format=crypt вказує формат хеша, системний crypt, тобто yescrypt або sha512crypt
# --wordlist=/usr/share/john/password.lst це словник слів для перебору, готовий у Kali
# --rules додає мутації слів, цифри в кінці, великі літери тощо

john --show --format=crypt ~/hashes.txt
# --show виводить уже підібрані паролі з попереднього запуску,
# вони зберігаються в ~/.john/john.pot
```

Щоб переконатись, що перебір працює, задай тестовому користувачу навмисно простий пароль 🔴

```bash
echo '<USER>:<ПРОСТИЙ_ПАРОЛЬ>' | sudo chpasswd
```

Після перевірки видали `~/hashes.txt` і `~/.john/john.pot`, там лишаються реальні хеші й підібрані паролі.

Відновлення пароля, якщо відома його структура, режим маски

```bash
john --format=crypt --mask='?l?l?l?d?d' ~/hashes.txt
# --mask='?l?l?l?d?d' задає шаблон пароля, 3 малі літери плюс 2 цифри
# ?l мала літера, 26 варіантів. ?u велика, 26. ?d цифра, 10. ?s спецсимвол, приблизно 33
```

Кількість ітерацій у найгіршому випадку дорівнює добутку варіантів кожної позиції. 26 помножити на 26, на 26, на 10, на 10 дає 1 757 600.

### 2.1.13 Політика паролів 🟢

```bash
grep -E '^(PASS_|LOGIN_RETRIES|ENCRYPT_METHOD|UMASK)' /etc/login.defs
# шукає рядки, що починаються на PASS_, LOGIN_RETRIES, ENCRYPT_METHOD або UMASK
# це і є політика, термін дії пароля, кількість спроб входу, алгоритм, права за замовчуванням

grep -v '^#' /etc/pam.d/common-password
# -v '^#' показує всі рядки, крім тих, що починаються з решітки, тобто без коментарів

cat /etc/security/pwquality.conf 2>/dev/null
# показує вимоги до складності пароля, якщо встановлено пакет pwquality
# 2>/dev/null приховує повідомлення про помилку, якщо файл чи пакет відсутній

sudo chage -l <USER>
# chage -l виводить терміни дії пароля конкретного користувача
```

### *2.1.14 Інші файли з хешами 🟢

Крім `/etc/shadow`, хеші або їх залишки можуть лежати в `/etc/gshadow`, `/etc/shadow-`, `/etc/passwd-`, `/var/backups/*.bak`, `/etc/security/opasswd`, `~/.john/john.pot`.

```bash
sudo grep -rlE '\$(y|6|5|1|2[aby])\$[^:]+' /etc /var/backups 2>/dev/null
# -r шукає рекурсивно по всіх підкаталогах
# -l виводить лише імена файлів зі збігом, не самі рядки з хешами
# шаблон у -E означає початок хеша, такий як $y$, $6$, $5$ і так далі
# /etc /var/backups це каталоги, де саме шукати
```

## 2.2 Створення і зміна акаунтів 🔴

```bash
sudo groupadd <GROUP>
# groupadd створює нову групу, додає рядок у /etc/group

sudo groupadd <GROUP2>

sudo useradd -m -s /bin/bash <USER>
# useradd -m створює користувача і домашній каталог /home/<USER>
# -s /bin/bash задає, яка оболонка входу буде в нього

sudo useradd -m -s /bin/bash <USER2>

sudo passwd <USER>
# passwd <USER> дає інтерактивно задати пароль цьому користувачу

sudo passwd <USER2>

sudo usermod -aG <GROUP> <USER>
# usermod -aG <GROUP> додає користувача до групи
# прапорець -a, append, обов'язковий, без нього існуючі групи користувача будуть замінені

sudo usermod -aG <GROUP>,<GROUP2> <USER2>
# через кому можна додати одразу до кількох груп
```

Перевірка

```bash
grep -E '<USER>|<USER2>' /etc/passwd
# показує рядки обох нових користувачів у /etc/passwd

sudo grep -E '<USER>|<USER2>' /etc/shadow
# те саме в /etc/shadow, хеш у звіті заміни на маску, не публікуй справжній

grep -E '<GROUP>|<GROUP2>' /etc/group
# перевіряє, що в /etc/group у четвертому полі з'явились імена цих користувачів
```

Прибрати

```bash
sudo userdel -r <USER>
# userdel -r видаляє користувача разом з домашнім каталогом

sudo userdel -r <USER2>
sudo groupdel <GROUP>
# groupdel видаляє групу

sudo groupdel <GROUP2>
```
