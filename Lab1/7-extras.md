# 7. Додатково: chroot, опції монтування (*)

Заготовки (`<DIR>` тощо) і позначки 🟢🟡🔴 дивись у [README](README.md).

## Терміни

**chroot** змінює, що процес вважає коренем файлової системи. Поза вказаним каталогом процес нічого не бачить.

**jail, в'язниця** каталог, підготовлений для запуску програми через chroot. Туди копіюються сама програма і все, що їй потрібно, зокрема бібліотеки.

**точка монтування** каталог, до якого підключений якийсь розділ або файлова система.

**nosuid / nodev / noexec** опції монтування, які діють на весь розділ одразу, незалежно від прав конкретних файлів.

## Запуск програми в ізольованому середовищі, chroot 🟡

```bash
mkdir -p <DIR>/{bin,lib,lib64}
cp /bin/ls <DIR>/bin/

ldd /bin/ls
# ldd показує, які динамічні бібліотеки потрібні програмі для запуску
# саме ці файли й треба скопіювати всередину <DIR>, інакше бінарник не стартує
```

```bash
mkdir -p <DIR>/lib64 <DIR>/usr/lib/x86_64-linux-gnu
cp /usr/lib/x86_64-linux-gnu/libc.so.6 <DIR>/usr/lib/x86_64-linux-gnu/
cp /lib64/ld-linux-x86-64.so.2 <DIR>/lib64/
# скопіювати решту бібліотек за тими самими шляхами, що показав ldd

sudo chroot <DIR> /bin/ls
# chroot <DIR> /bin/ls запускає /bin/ls, вважаючи <DIR> коренем файлової системи
# програма не бачить нічого поза ним
```

Відношення до безпеки. chroot обмежує процес від доступу до решти файлової системи, застосовується, зокрема, для ізоляції FTP чи SSH. Та це не є повноцінною ізоляцією, на відміну від контейнерів. root усередині chroot за певних умов може з нього вийти, це називається chroot escape.

Прибрати

```bash
rm -r <DIR>
```

## Опції монтування, що впливають на безпеку 🟢

```bash
cat /proc/mounts | grep -E 'nosuid|nodev|noexec'
# /proc/mounts це список активних точок монтування з їх опціями
```

Опція `nosuid` означає, що біти SUID і SGID на цьому розділі ігноруються, навіть якщо вони встановлені на файлі.

Опція `nodev` означає, що файли пристроїв на цьому розділі не трактуються як реальні пристрої.

Опція `noexec` означає, що будь-яке виконання програм із цього розділу заборонено.

Ці опції зазвичай стоять на `/tmp`, `/dev`, `/proc`, `/run` та інших службових точках. Саме тому демонстрацію SUID, пункт 4.3 у `3-permissions.md`, потрібно робити в домашньому каталозі, а не в `/tmp`. Там SUID просто не спрацює, незалежно від прав файлу.
