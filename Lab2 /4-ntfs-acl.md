# 4-ntfs-acl.md

## ACL, дозволи NTFS, права доступу

### Терміни

**ACL (Access Control List)** список записів ACE, прикріплений до файлу чи папки. Кожен ACE каже: цьому суб'єкту (користувачу/групі/вбудованому принципалу) дозволено або заборонено ось цю дію.

**ACE (Access Control Entry)** один запис в ACL: тип (дозволити/заборонити), суб'єкт, набір прав, звідки успадковано, до чого застосовується.

**Успадкування** папка/файл за замовчуванням отримує ACL батьківської папки; можна вимкнути (`/inheritance:r`), щоб об'єкт мав лише власні явні записи.

**Явна заборона (deny)** позначається `(N)`, завжди стоїть першою в списку і перекриває будь-який дозвіл, включно з успадкованим і виданим через групу.

**Ефективні права (effective access)** підсумковий доступ конкретного користувача з урахуванням усіх його груп, явних дозволів, успадкування й заборон — рахується системою автоматично.

### Приклад політики контролю доступу (шаблон для звіту) 🟢

Перед тим як будувати ACL командами, корисно словами сформулювати правила — ось шаблон:

1. Кожен користувач працює під особистим обліковим записом; спільні записи заборонені, «Гость» вимкнений.
2. Права адміністратора — лише в окремого облікового запису (`<ADMIN>`), звичайні користувачі без привілеїв.
3. Мінімальні права: кожен отримує лише потрібний доступ.
4. Дозволи видаються групам, а не окремим користувачам; явний дозвіл отримує лише власник на свою папку.
5. У папках користувачів успадкування від кореня диска вимкнено.
6. Власник папки може обмежувати доступ до вкладених об'єктів явною забороною.
7. Явна заборона має пріоритет над будь-яким дозволом.

Таблицю правил зручно вести так (власник / явні / через групи / успадковані / явні заборони — заповни своїми іменами):

| Об'єкт | Власник | Явні | Через групи | Успадковані | Явні заборони |
|---|---|---|---|---|---|
| `<FOLDER>` | `<USER>` | `<USER>`: F | `<GROUP>`: M; `<GROUP2>`: RX | — | — |
| `<FOLDER>\Sub` | `<USER>` | — | — | від `<FOLDER>` | — |

### ACL папки й файлу, типи суб'єктів 🟡

```cmd
mkdir <FOLDER>
type nul > <FOLDER>\test.txt

icacls <FOLDER>
icacls <FOLDER>\test.txt
:: виводить ACL у консолі — той самий список, що й у Провіднику: Властивості → Безопасность → Дополнительно
```

Дозволи можна призначати: конкретним **користувачам**, **групам**, **вбудованим суб'єктам безпеки** (Все, СИСТЕМА, Прошедшие проверку), у домені — ще й комп'ютерам.

### Стандартні й особливі дозволи NTFS

13 особливих дозволів складають стандартні. Головне, що треба знати:

| Стандартний дозвіл | Скорочення | Основні особливі дозволи всередині |
|---|---|---|
| Повний доступ | F | усі 13, включно зі зміною дозволів і власника |
| Зміна | M | читання/виконання + запис + видалення |
| Читання й виконання | RX | читання вмісту, атрибутів, запуск програм, обхід папки |
| Список вмісту папки | — | те саме, що RX, але тільки для папок |
| Читання | R | тільки читання вмісту й атрибутів |
| Запис | W | створення файлів/папок, запис атрибутів |

### Призначення прав: явно, через групи, успадкування вимкнене 🔴

```cmd
icacls <FOLDER> /grant *S-1-5-18:(OI)(CI)F *S-1-5-32-544:(OI)(CI)F
:: *S-1-5-18 = СИСТЕМА, *S-1-5-32-544 = Администраторы
:: SID замість назв — команда не залежить від мови системи

icacls <FOLDER> /grant <USER>:(OI)(CI)F <GROUP>:(OI)(CI)M <GROUP2>:(OI)(CI)RX
:: (OI) поширюється на вкладені файли, (CI) на вкладені папки
:: F повний доступ, M зміна, RX читання й виконання

icacls <FOLDER> /inheritance:r
:: прибирає успадковані від кореня диска записи
:: ВАЖЛИВО: спочатку /grant, потім /inheritance:r — щоб не втратити власний доступ

icacls <FOLDER>\Sub /deny <GROUP2>:(OI)(CI)F
:: явна заборона; у виводі icacls позначається (N), стоїть першою в списку

icacls <FOLDER> /setowner <USER> /T
:: призначає <USER> власником папки й усіх вкладених об'єктів
```

**Перевірка:**

```cmd
dir /s /b <FOLDER>
dir /q <FOLDER>
:: /q показує власників файлів і папок
icacls <FOLDER>
```

### Явна заборона доступу іншому користувачу 🔴

```cmd
icacls <FOLDER>\Sub /deny <USER2>:(OI)(CI)F
icacls <FOLDER>\doc1.txt /deny <USER2>:F
:: запускай від власника <FOLDER>, якщо раніше доступ був дозволений через групу

icacls <FOLDER>\Sub
icacls <FOLDER>\doc1.txt
:: перевірка: <USER2>:(N) першим рядком
```

Перевір від імені `<USER2>`:

```cmd
type <FOLDER>\doc1.txt    :: Access is denied
dir <FOLDER>\Sub          :: File Not Found — так dir повідомляє про відсутність права на перегляд
type <FOLDER>\doc2.txt    :: працює — заборона діє лише на заборонені об'єкти
```

### Передача права власності 🔴

```cmd
icacls <FOLDER> /grant <USER3>:(RC,WO)
:: (RC,WO) = Read Control + Write Owner: можливість забрати папку, але НЕ доступ до вмісту
```

Від імені `<USER3>`:

```cmd
icacls <FOLDER> /setowner <USER3>
:: тепер <USER3> власник, але ACL ще старий — вмісту досі немає (dir дає File Not Found)

icacls <FOLDER> /grant <USER3>:(OI)(CI)RX
:: власник завжди може міняти ACL на свій об'єкт — щойно отриманою владою видає собі доступ
```

Повернути початковий стан (від імені `<USER>`):

```cmd
icacls <FOLDER> /setowner <USER>
icacls <FOLDER> /remove:g <USER3>
```

**Висновок.** Сама передача власності **не змінює ACL** й не відкриває вміст автоматично. Але власник завжди може змінити дозволи на свій об'єкт — цим і користується новий власник.

### Ефективні права 🟢

```
Властивості папки → Безопасность → Дополнительно → Действующие права доступа
Выберите пользователя → <USER> → Просмотр действующих разрешений
```

Windows рахує підсумковий доступ з урахуванням усіх груп користувача, явних дозволів, успадкування й заборон. Зелена позначка — право є, червоний хрестик — немає. Саме тут видно ефект явної заборони: якщо група має RX на папку, а конкретному користувачу з цієї групи заборонено явно — ефективні права покажуть «немає доступу», незважаючи на групу.

**Головний висновок усього файлу.** Пріоритет завжди такий: **явна заборона > явний дозвіл > дозвіл через групу > успадкований дозвіл**. Власник об'єкта завжди може змінити його ACL, навіть якщо сам собі до цього не мав доступу до вмісту.
