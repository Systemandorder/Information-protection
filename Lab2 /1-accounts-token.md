## Облікові записи, маркер доступу, SID

### Терміни

**SID (Security Identifier)** унікальний ідентифікатор користувача чи групи в Windows — аналог UID/GID у Linux, але текстовий і структурований.

**Маркер доступу (access token)** об'єкт, який система видає процесу при вході: містить SID користувача, SID усіх його груп з атрибутами, рівень цілісності та список привілеїв. Усі перевірки прав під час роботи процесу йдуть через цей маркер, не через повторний запит до бази користувачів.

**RID (Relative Identifier)** останнє число в SID — номер конкретного облікового запису/групи на цьому комп'ютері. 500 — вбудований адміністратор, 501 — гість, нові користувачі з 1000.

**Рівень цілісності (integrity level)** додатковий бар'єр понад звичайні права: Low/Medium/High/System. Навіть маючи дозвіл за ACL, процес з нижчим рівнем цілісності не може писати в об'єкт з вищим.

**UAC (User Account Control)** механізм, через який адміністратор за замовчуванням працює зі звуженим маркером (група «Адміністратори» лише для заборон, середній рівень цілісності) і отримує повний маркер лише після підтвердження підвищення.

### Облікові записи та маркер доступу 🟢

```cmd
winver
:: показує редакцію та збірку Windows

whoami /all
:: виводить повний маркер доступу поточного процесу:
:: ім'я та SID користувача, усі групи з SID і атрибутами,
:: рівень цілісності, список привілеїв
:: виконай команду і в звичайній консолі, і в консолі "від імені адміністратора" — порівняй

net user
:: список локальних облікових записів

wmic useraccount get name,sid
:: імена та SID усіх облікових записів
:: кириличні імена можуть виводитись як "?????" через кодову сторінку консолі — на сам SID це не впливає

net user <USER>
:: параметри конкретного облікового запису: активний чи ні,
:: коли змінено пароль і коли спливає, членство в групах

net localgroup
:: список локальних груп

net localgroup <GROUP>
:: склад конкретної групи
```

**Порівняння звичайної консолі та консолі адміністратора.** У звичайній консолі група «Адміністратори» в маркері присутня лише як «Group used for deny only» (діє тільки для заборон), рівень цілісності середній, активних привілеїв мало. У консолі «від імені адміністратора» та сама група активна (Mandatory group, Enabled), рівень цілісності високий, активних привілеїв значно більше. Це і є UAC: звужений маркер за замовчуванням, повний — лише після підтвердження.

### SID у Process Explorer 🟢

```
procexp64.exe          :: запустити від імені адміністратора
```

Вкладка **Security** у властивостях будь-якого процесу показує:
- **User** — ім'я та SID користувача, під яким працює процес;
- **Group** — усі групи маркера доступу;
- **Privilege** — список привілеїв маркера, увімкнені й вимкнені.

### Структура SID

Приклад `S-1-5-21-<ID_КОМП'ЮТЕРА>-<RID>`:

| Частина | Значення |
|---|---|
| `S` | ознака, що це SID |
| `1` | версія структури (revision) |
| `5` | ідентифікаційний орган: 5 = NT Authority (Windows); для «Все» це 1 (World), для консольного входу — 2 (Local) |
| `21-...-...-...` | sub-authority — унікальний ID цього комп'ютера/домену, на іншій машині інший |
| останнє число | RID — номер облікового запису на цьому комп'ютері: 500 адміністратор, 501 гість, з 1000 нові |

### Типи SID у системі

| Тип | Формат | Приклад |
|---|---|---|
| Користувачі/групи, створені на машині | `S-1-5-21-<ID>-<RID>` | звичайний користувач |
| Вбудовані (BUILTIN) групи | `S-1-5-32-<RID>` | 544 — адміністратори, 545 — користувачі |
| Спеціальні, однакові скрізь | фіксований SID | `S-1-1-0` Everyone, `S-1-5-18` SYSTEM, `S-1-5-19` LOCAL SERVICE, `S-1-5-20` NETWORK SERVICE, `S-1-5-11` Authenticated Users |
| Logon SID | `S-1-5-5-X-Y` | унікальний для кожного сеансу входу, обмежує доступ об'єктів сесії лише процесами цього сеансу |

### Маркер непривілейованого користувача 🟢

```cmd
whoami /all
```

Виконай під звичайним (не адміністративним) обліковим записом і порівняй з адміністраторським: у непривілейованого користувача немає групи «Адміністратори» в маркері, рівень цілісності середній, активних привілеїв 1–2 (зазвичай лише `SeChangeNotifyPrivilege`). Він не може завантажувати драйвери, налагоджувати чужі процеси, змінювати чужі файли без дозволу.

**Висновок.** Маркер доступу — це «посвідчення» процесу: хто він (SID), у яких групах (SID груп), наскільки йому довіряють (рівень цілісності) і що йому дозволено системно (привілеї). UAC звужує це посвідчення для адміністратора за замовчуванням, щоб звичайна помилкова чи шкідлива програма не отримувала адміністративних прав автоматично.
