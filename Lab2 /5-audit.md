
## Політика аудиту та аудит файлової системи

### Терміни

**Аудит (auditing)** механізм, який записує в журнал безпеки спроби доступу до об'єктів (успішні й/або невдалі), не змінюючи сам доступ. Аудит потрібно ввімкнути **у двох місцях одночасно** — у політиці системи та на самому об'єкті — інакше записів у журналі не буде.

**Подія аудиту** запис у журналі «Безопасность» (Event Viewer) з кодом: хто, що, коли, яким процесом зробив.

### Політика аудиту (перегляд) 🟢

```
secpol.msc
Local Policies → Audit Policy                                            :: базова, 9 категорій
Advanced Audit Policy Configuration → System Audit Policies → Object Access   :: детальніша, 14 підкатегорій
```

За замовчуванням усі категорії «Нет аудита» / «Не настроено» — аудит файлової системи треба вмикати вручну.

### Налаштування аудиту створення файлів 🔴

```cmd
set G={0CCE921D-69AE-11D9-BED3-505054503030}
:: GUID підкатегорії "Файловая система" (Object Access → File System)
:: в Home немає secpol.msc, тому вмикаємо через auditpol

auditpol /set /subcategory:%G% /success:enable /failure:enable
:: вмикає аудит успішних і невдалих спроб для цієї підкатегорії

auditpol /get /subcategory:%G%
:: перевірка: має бути "Success and Failure"

mkdir <FOLDER>\AuditTest
echo hi> <FOLDER>\AuditTest\<FILE>
```

Налаштування аудиту **на самій папці** (у Провіднику — друга половина, без якої записів не буде):

```
<FOLDER>\AuditTest → Свойства → Безопасность → Дополнительно → Аудит → Добавить
Субъект: Все; Тип: Все; Применяется к: Для этой папки, её подпапок и файлов
Права: «Создание файлов / запись данных», «Создание папок / дозапись данных»
```

**Відтворення й перевірка:**

```cmd
echo hi> <FOLDER>\AuditTest\<USER>_file.txt      :: під звичайним користувачем
echo hi> <FOLDER>\AuditTest\<ADMIN>_file2.txt     :: під адміністратором

eventvwr.msc
:: Журналы Windows → Безопасность → Фильтр: коды событий 4656,4663
```

Журнал «Безопасность» під звичайним користувачем **не відкривається** («Отказано в доступе») — переглядати його може лише адміністратор (саме це і є практична демонстрація права «Управление аудитом и журналом безопасности» з `2-policy-secpol.md`).

### Основні коди подій журналу безпеки

| Код | Подія |
|---|---|
| 4624 / 4625 | успішний / невдалий вхід у систему |
| 4634 | вихід із системи |
| 4656, 4663 | запит дескриптора об'єкта; спроба доступу до об'єкта |
| 4660 | видалення об'єкта |
| 4670 | зміна дозволів об'єкта |
| 4672 | видано особливі привілеї при вході |
| 4688 | створення нового процесу |
| 4719 | зміна політики аудиту |
| 4720 / 4726 | створено / видалено обліковий запис |
| 4732 | користувача додано до локальної групи |

**Висновок.** Аудит не захищає сам по собі — він лише фіксує факт доступу для подальшого розслідування. Маска операції в події 4663 (наприклад `0x6` = запис даних + дозапис) показує, саме які з налаштованих прав спрацювали.

### Прибрати за собою 🟡

```cmd
auditpol /set /subcategory:%G% /success:disable /failure:disable
rmdir /s /q <FOLDER>\AuditTest
```
