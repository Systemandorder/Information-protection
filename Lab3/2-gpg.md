# Частина 2. GPG 

Дві ролі, User1 на одній машині, User2 на іншій. Нижче приклад для User1 на клієнті і User2 на сервері, за потреби значення міняються місцями.

## 2.1 Створення пари ключів 🟡

```bash
gpg --gen-key
# запускає майстер створення пари ключів
# питає ім'я, email і парольну фразу для захисту таємного ключа
# якщо не питає ім'я й email одразу, використати gpg --full-generate-key

gpg --list-secret-keys
gpg --list-public-keys
# list-secret-keys показує свій таємний ключ
# list-public-keys показує всі відкриті ключі у в'язці, свої й імпортовані
```

## 2.2 Експорт, обмін і підпис файлу 🟡

```bash
gpg --export -a "User1" > user1.pubkey
# --export -a виводить відкритий ключ у текстовому форматі armor
# результат перенаправляється у файл

scp user1.pubkey <USER2>@<SERVER_IP>:
# передає відкритий ключ на іншу машину, щоб та могла перевіряти підпис User1

date +%s > testfile
gpg --clearsign testfile
# clearsign підписує файл, лишаючи текст читабельним, підпис додається навколо нього
# результат це новий файл testfile.asc

scp testfile.asc <USER2>@<SERVER_IP>:
```

## 2.3 Перевірка підпису і шифрування 🟡

На машині User2

```bash
gpg --import user1.pubkey
# додає відкритий ключ User1 у свою в'язку ключів

gpg --verify testfile.asc
# перевіряє підпис файлу відкритим ключем автора
# результат Good signature означає, що файл справді підписаний User1 і не змінений
```

Шифрування файлу для User1 (на машині User2, після обміну ключами)

```bash
gpg -e -r user1@gmail.com -a test.file
# -e шифрує файл, -r вказує одержувача за email або ID ключа
# розшифрувати такий файл може лише власник відповідного таємного ключа

gpg -e -s -r user1@gmail.com -a test1.file
# -s додатково підписує файл власним таємним ключем перед шифруванням
# отримувач і розшифрує файл, і перевірить, хто його надіслав
```

## 2.4 Розшифрування і fingerprint 🟢

На машині User1

```bash
gpg --import user2.pubkey
gpg --fingerprint user2@gmail.com
# fingerprint показує повний відбиток ключа для звірки автентичності

gpg test.file.asc
gpg test1.file.asc
# без прапорців gpg сам визначає дію за вмістом файлу
# для шифрованого файлу це розшифрування, питає парольну фразу свого таємного ключа
# для другого файлу також виводить Good signature, бо він ще й підписаний
```

## Прибрати

```bash
gpg --delete-secret-and-public-key <KEY_ID>
# видаляє пару ключів з в'язки
# KEY_ID береться з виводу --list-public-keys, останні символи відбитка
```
