# Лаба 3. Криптографічні механізми захисту даних

Розбір практичної №3 за трьома частинами методички. Два стенди, клієнт і сервер, в одній мережі Host-only.

## Як читати команди із заготовками

Заготовка пишеться так `<ЩОСЬ_ВЕЛИКИМИ>`. Дужки `<` `>` теж треба прибрати.

| Заготовка | Що підставити | Приклад |
|---|---|---|
| `<CLIENT_IP>` | IP адреса клієнтської VM | `192.168.104.129` |
| `<SERVER_IP>` | IP адреса серверної VM | `192.168.104.128` |
| `<IFACE>` | назва мережного інтерфейсу | `eth0` |
| `<USER>`, `<USER2>` | ім'я користувача на сервері | `system` |
| `<NAME>` | прізвище й ім'я латиницею | ` Oleksii` |
| `<GROUP>` | група | `FB-56` |
| `<NUMBER>` | номер залікової книжки | `3000056789012` |
| `<KEY_ID>` | ID GPG ключа | `46267D57` |

## Рівні ризику

| Позначка | Значення |
|---|---|
| 🟢 | Лише читає або перевіряє, нічого не змінює. Безпечно. |
| 🟡 | Створює файли, ключі чи тимчасові дані. Безпечно, але потім прибери за собою. |
| 🔴 | Змінює систему, встановлює службу, додає довірений сертифікат. Варіант відкату або прибирання є в кінці відповідного файлу. |

## Запис у звіт

Звіт це один текстовий файл з виконаними командами і результатами, без скріншотів.

```bash
export TERM=dumb
script report.txt
# TERM=dumb вимикає кольори й керівні коди термінала, щоб звіт не засмічувався
# script записує все, що відбувається в терміналі, у файл
# завершити запис командою exit
```

Якщо команди виконуються на двох машинах, запис веди окремими файлами на кожній, потім склей

```bash
scp <USER>@<SERVER_IP>:report_server.txt .
cat report_client.txt report_server.txt > report.txt
```

Паролі й парольні фрази у звіт не потрапляють, термінал їх не відображає при введенні.
